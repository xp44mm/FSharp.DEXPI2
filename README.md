# FSharp.DEXPI2

用 C++（主）+ F#（record 镜像）落地 [DEXPI 2.0](https://dexpi.org) 信息模型的实验仓库。
DEXPI（Data Exchange in the Process Industry）是过程工业 P&ID 数据交换标准，本仓库从
官方 UML/XMI 出发，生成 C++ 原生类库，并围绕"一个箱子 + 一个管嘴 + 一个阀门 +
一段管道 + 排放"这条最小管线做验证。

## 怎么读这个模型（重要）

**UML 定义只有一份：`DEXPI2.0-UML/Dexpi.xmi`。** 它派生成 C++ 头文件，
平时**只读一份就够**——推荐读：

> **`Dexpi2.Cpp/Generated/dexpi2.hpp`**（约 280 KB，纯头文件，无实现）

理由：
- C++ 头文件就是"纯声明"，跟 UML 类图一一对应；多继承直接写在 `class X : public A, public B, public C`
  上，mixin 父类一眼看完（例：`class Nozzle : public ConceptualObject, public SensingLocation,
  public PipingNodeOwner, public PipingSourceItem, public PipingTargetItem`）。
- 命名空间即 UML package：`dexpi2::core`、`dexpi2::core::diagram`、`dexpi2::plant::processequipment`、
  `dexpi2::plant::piping`、`dexpi2::plant::instrumentation` …
- 每个类上方有注释 `// DEXPI 2.0 model class Xxx (XMI id ID...)`，可拿 id 回 EA 定位。
- multiplicities 直接翻译成类型：模型引用 `shared_ptr<X>`，多值 `vector<shared_ptr<X>>`，
  可选 `optional<T>`。
- 抽象类标 `[abstract in DEXPI]` 并把构造函数设为 protected。

**阅读姿势**：不要从头翻（7600 行）。开头 17–500 行是前向声明索引，当目录用；
想查哪个类，Ctrl+F 类名跳到 `class Xxx : public ...` 的真正定义处（每个类 10–20 行）。

## 各项目说明

### `Dexpi2.Cpp/Generated/dexpi2.hpp`  —  读模型的主入口 ★
- **是什么**：`Dexpi2CppGen` 从 `Dexpi.xmi` 生成的全量 C++ 头文件，DEXPI 2.0 所有类都在这里。
- **怎么用**：当作"UML 类图的代码版"来查。想知道 `Tank` 有哪些属性、继承自谁、跟 `Nozzle`
  什么关系，直接在这个文件里搜类名。
- **重新生成**：改了 XMI 后跑 `Dexpi2CppGen`，不要手改这个文件（顶部有 `// <auto-generated>`）。

### FSharp.DEXPI2/  —  DEXPI 2.0 管线对象的 F# record 镜像
- **类型**：`netstandard2.0` 类库，F#。
- **内容**：用 record 直接镜像 DEXPI 2.0 的管线对象链：`PlantModel → PipingNetworkSystem → Segments
  → Items / Connections`、`Tank → Nozzle → PipingNode`。管道组件是判别联合（`PipeTee`、`Sensorwell`、
  `OperatedValve`、`CheckValve`、`PipeOffPageConnector`、`PipeReducer` …），集合一律用 F# `list`，
  跨对象引用在工厂模型里"在位内联"。
- **定位**：对照 P&ID 图看的最小对象模型；全量定义仍看 `dexpi2.hpp`。

### Dexpi2.Cpp/  —  C++ 原生静态库
- **类型**：MSVC v145 / C++20 / x64 静态库（`.vcxproj`）。
- **内容**：include 上面那个 `Generated/dexpi2.hpp`，用 C++ 原生多继承直接映射 XMI mixin；
  多值属性 `std::vector<T>`，可选 `std::optional<T>`，模型引用 `std::shared_ptr<T>`。
- **状态**：头文件已生成；XML 反序列化、VS 类设计器类图待做。

### Dexpi2CppGen/  —  C# 代码生成器
- **类型**：`net` 控制台工程（`.csproj`）。
- **内容**：读 `DEXPI2.0-UML/Dexpi.xmi`，产出 `Dexpi2.Cpp/Generated/dexpi2.hpp`。
  关键文件：`XmiParser.cs`（XMI 解析）、`Model.cs`（内部模型）、
  `TypeMapper.cs`（类型映射）、`CppEmitter.cs`（C++ 代码生成）、`ReportWriter.cs`（生成报告）。
- **在 slnx 中**：和 Dexpi2.Cpp 配对。

### Dexpi2.CSharp/  —  生成的 C# 扁平化类库
- **类型**：`netstandard2.0` 类库，C#（RootNamespace `Dexpi2`）。
- **内容**：`Dexpi2.CSharp.Generator` 从 `Dexpi2.Cpp/Generated/dexpi2.hpp` 生成的零继承类库
  （`Dexpi2.Core.cs` / `Dexpi2.Plant.cs` / `Dexpi2.Process.cs` / `Dexpi2.Auxiliaries.cs`），
  消除 UML mixin 多继承，抽象类仍标 `abstract`。详见 `Dexpi2.CSharp/README.md`。

### Dexpi2.CSharp.Generator/  —  F# 代码生成器
- **类型**：F# 控制台工程（`.fsproj`，slnx 中不参与 Debug 构建）。
- **内容**：读 `Dexpi2.Cpp/Generated/dexpi2.hpp`，按与 C++ 扁平化相同的规则产出上面的 C# 类库。
  用法：`Dexpi2CSharpGenerator [inputHpp] [outDir]`。

### DEXPI2.0-UML/  —  官方 UML / XMI 源材料（唯一事实源）
- `Dexpi.xmi`：标准版本 XMI（Enterprise Architect 17 导出）。
- `DEXPI 2.0 EA Information Model.qea/.xml`：Sparx EA 工程及其 XMI 导出。
- `DEXPI 2.0 EA HTML export/`：静态 HTML 类图（在线版 <https://dexpi.org/static/ea_dexpi_spec_2.0/>）。
- 所有代码生成都以这个目录为输入。

### Specification-V2.0.0/  —  官方规范
- DEXPI 2.0 官方规范文档（PDF / 发布包），最新版见 <https://gitlab.com/dexpi/Specification/-/releases>。

### 根目录散文件
- `pid.png`：本仓库建模所参照的 P&ID 草图（箱 + 液位线 + 底嘴 + 手阀 + 管线 + 排放箭头）。

## 最小管线（pid.png → 概念模型）

参照图里的走向：

```
V-101 (Tank)
  └─ N1 (bottom nozzle)
       └─ XV-101 (ShutOffValve)
            └─ PL-101 (DN50)
                 └─ To Sewer / Atmosphere
```

验证入口在 `FSharp.DEXPI2.Test`：按同一张图构建的管线树实例
（`InPlaceTree` 罐 → 阀门 → 异径管 → 排出口；`PumpTree` 泵回路；`TeeTree` 三通一分二；
`SensorwellTree` 两罐间传感器套管测点），每个树都以 `PlantModel` 为工厂入口、
在位内联对象，并断言段与连接（`Connections`）的拓扑。

## 分段规则：共享管件（异径管 / 三通）必须单独成段

`PipingNodeOwner` 的每一项只属于**一个**段的 `Items`（值语义，不是引用）。
而异径管（`PipeReducer`）和三通（`PipeTee`）是**被多段共享的节点**：

- 异径管：一个入口 + 一个出口，同时是上游段的末端和下游段的始端，被两个段引用；
- 三通：一个入口 + 直通 + 支管，最多同时被三个段引用。

因此分段规则是：

1. 共享管件必须**单独放进自己的段**（单例段），段内 `Items` 只含这一个管件；
2. 该段必须有一个**名称**：`SegmentNumber` 即名称，作为被其他段引用的句柄；
3. 其他段用 `PipingNodeOwner.PipingNetworkSegmentSingleton(tag = "段名")` 引用它，
   而不是把管件重复内联进多个段的 `Items`。

构造单例段用 `PipingNetworkSegment.tee` / `PipingNetworkSegment.reducer`
（`DEXPI2\PipingNetworkSegment.fs`）：

```fsharp
PipingNetworkSegment.reducer "S2"  // 异径管单例段
PipingNetworkSegment.tee "T1"      // 三通单例段
```

实例：

- `InPlaceTree`：S2 是异径管单例段，S1、S3 用 `PipingNetworkSegmentSingleton(tag = "S2")` 引用；
- `PumpTree`：S2（XR-101）、S5（XR-102）分别是罐出口侧、泵出口侧异径管的单例段，
  分别由 S1/S3、S4/S6 引用。
